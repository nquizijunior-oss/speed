## Shared editing across all browsers (Supabase)

The app now supports shared persistence for edits. Without Supabase variables it falls back to the existing browser-local behavior; with Supabase configured, edits are stored centrally and synchronized to other browsers.

1. Create a Supabase project.
2. Open **SQL Editor** and run `supabase_shared_edits.sql` from this project.
3. Copy `.env.example` to `.env.local` and fill in the Supabase project URL and anonymous key from **Project Settings → API**.
4. Run `npm install` and `npm run dev`.
5. For Vercel, add the same `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` values under **Project Settings → Environment Variables**, then redeploy.

The current prototype uses public RLS policies because the existing app login is client-side. If this will contain real personal/customer data, add Supabase Auth and tighten the policies before production use.
